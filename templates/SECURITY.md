# Security policy

## Reporting a vulnerability

Please do not open a public issue, pull request or discussion for a
security problem.

Report it privately through GitHub: on this repository's **Security**
tab, choose **Report a vulnerability**. Only the maintainers see the
report.

Include what you can of: the affected file or package, the version or
commit, the steps that show the problem, and what an attacker gains.

## What happens next

1. **We confirm** that we have the report, and tell you whether we
   reproduce it.
2. **We fix it** in private, and may ask you to check the fix.
3. **We release** the fix on `main`, then **publish an advisory** on
   this repository with a CVE, requested through GitHub.
4. **We credit you** in the advisory, by the name you give us, unless
   you ask not to be named.

Please keep the problem private until the advisory is published.

## Supported versions

Only `main` is supported. Fixes are made there and are not backported.

A distribution built from these templates is maintained by whoever
publishes it: report a problem in that distribution to its publisher,
and a problem in the templates here.
